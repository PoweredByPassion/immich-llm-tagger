## 📖 Обзор

Когда фото с телефона попадают в резервную копию (синхронизация iCloud, Google Photos или мобильное приложение Immich), личная временная шкала быстро забивается временным мусором: **снимками экрана, чеками, счетами, документами, реакционными мемами и рекламой**.

**Immich LLM Tagger** — лёгкий сервис автоматизации для самостоятельного хостинга, сделанный специально под Immich. Мультимодальные визуальные модели (DeepSeek-VL, Qwen-VL, GPT-4o, Ollama или любой Vision API, совместимый с OpenAI) используются так:

1. **Мусор сам уходит в архив**. Снимки экрана, мемы и одноразовые картинки убираются с основной временной шкалы в архив Immich.
2. **Раскладка по альбомам**. Счета и сканы бумаг попадают в `Documents`, удостоверения личности — в `ID Documents`.
3. **Защита приватности**. Документы, пароли и чувствительные карты помечаются тегами `sensitive`.
4. **Живые фото остаются на месте**. Настоящая жизненная съёмка не трогается и остаётся на основной временной шкале.
5. **Полная обратимость**. Каждое действие пишется в журнал изменений, и его можно откатить одним щелчком.

## ✨ Возможности

- 🧠 **Мультимодальное зрение**. Подходит любой Vision API, совместимый с OpenAI (`/v1/chat/completions`). Работают DeepSeek-VL, Qwen2.5-VL, MiniCPM, GPT-4o, Claude и локальный Ollama.
- 🧹 **Чистая основная временная шкала**. На шкале остаётся только настоящая съёмка. Мусор безопасно уходит в архив Immich.
- 📁 **Автоматическая раскладка по альбомам**. Документы и удостоверения сами попадают в отдельные альбомы Immich.
- ⚡ **Два способа запуска**:
  - **Webhook в реальном времени**. Срабатывает сразу, когда фото загружают или помечают тегом в Immich.
  - **Запасной поллинг**. Периодическое сканирование с настраиваемым интервалом, чтобы не пропустить ни один объект.
- 🔒 **Параллельность и аренда блокировки**. Атомарный захват аренды в SQLite не даёт обработать один и тот же объект дважды, даже если воркеры работают параллельно.
- ↩️ **Откат в один клик и обратимые операции**. Полный журнал аудита (`change_log`) позволяет откатить любую задачу в любой момент.
- ⭐ **Оценки и описания (переключатель на каждый тег)**. Визуальная модель может заодно заполнить звёздную оценку и описание, встроенные в Immich. **Писать ли их, решает каждый тег** (та же модель, что у архива / альбома / пропуска). Оценка значит «насколько хорошо выглядит фото», а не важность и не ценность как память. Защита по каждому полю никогда не затирает то, что вы написали сами.
- 🛡️ **Неразрушающий сброс в своих границах**. Опасная зона сбрасывает только отмеченные измерения (теги / классификация / оценка / описание) и трогает только объекты, которые уже обрабатывала эта система. Объекты тегов и теги, которые вы расставили сами на других фото, остаются нетронутыми.
- 🎨 **Тёмная панель управления в стиле Linear**. Собрана на FastAPI, Tailwind CSS, Alpine.js и HTMX. Есть живой прогресс по SSE, карточки объектов и визуальные редакторы правил.

## 🚀 Быстрый старт (минимальный рабочий пример)

Полный экземпляр поднимается за **3 минуты** через Docker Compose.

### Шаг 1. Клонировать репозиторий и создать `.env`

Образ уже собран и публикуется в GHCR при каждой отправке в репозиторий, поэтому нужны только файл compose и `.env`. Локальная цепочка сборки (Python / Node / Tailwind) не требуется.

```bash
git clone git@github.com:PoweredByPassion/immich-llm-tagger.git
cd immich-llm-tagger
cp .env.example .env
```

Впишите в `.env` адрес своего Immich и учётные данные Vision LLM:

```dotenv
# Immich Server Connection
IMMICH_URL=http://your-immich-ip:2283
IMMICH_API_KEY=your_immich_api_key

# OpenAI-Compatible Vision LLM Endpoint
LLM_BASE_URL=http://host.docker.internal:7863  # Or your LLM provider URL
LLM_API_KEY=your_llm_api_key
LLM_MODEL=deepseek-vl                         # Your vision model name
DATA_DIR=/data
AUTH_PASSWORD=                                # Set to enable password auth (public deployments); empty = disabled
```

> **Локальный LLM**. Если сервис модели запущен прямо на машине-хосте Docker (например порт 7863 или 11434 у Ollama), оставьте `host.docker.internal`, чтобы контейнер видел сеть хоста.

### Шаг 2. Запустить сервис

Команда скачивает готовый образ `ghcr.io/poweredbypassion/immich-llm-tagger:latest` и запускает контейнер:

```bash
docker compose up -d
```

Откройте в браузере **`http://localhost:8080`**.

### Шаг 3. Импортировать готовые правила

В репозитории два локализованных шаблона правил:
- **`autotag-config.en.yaml`**: обычные английские теги (`screenshot`, `document`, `meme`...) и английский промпт (тег очереди: `unclassified`).
- **`autotag-config.zh.yaml`**: обычные китайские теги (`截图`, `文档`, `表情包`...) и китайский промпт (тег очереди: `未分类`).

**Как импортировать**:
1. В веб-интерфейсе откройте **Система → Перенос конфигурации** (`http://localhost:8080/config/transfer`).
2. Нажмите **Импорт конфигурации**, выберите [`autotag-config.en.yaml`](autotag-config.en.yaml) (или [`autotag-config.zh.yaml`](autotag-config.zh.yaml)) и отправьте форму.
3. Все теги (включая переключатели **Писать оценку** / **Писать описание** и правила архива и альбомов), пороги и шаблоны промптов подставятся сразу.

## 🔌 Настройка на стороне Immich (2 режима запуска)

Immich LLM Tagger умеет запускаться двумя способами. Выберите тот, который лучше ложится на вашу схему.

### Режим 1. Автоматический поток (новые загрузки без рук)

Настройте встроенный Workflow Immich: новые загрузки сами получают тег `unclassified`, а Tagger получает уведомление.

1. В веб-интерфейсе Immich откройте **Administration → Workflows** (Immich v1.118+).
2. Нажмите **Create Workflow** и назовите поток `Auto Classify`.
3. Задайте **Trigger**: выберите `AssetCreate` (когда загрузка завершилась) или `AssetMetadataExtraction`.
4. Добавьте **Step 1 — Add Tag**:
   - Action: `Add Tag`
   - Tag Name: введите `unclassified` (или `未分类`, если используете китайскую конфигурацию).
5. Добавьте **Step 2 — Trigger Webhook**:
   - Action: `Trigger Webhook`
   - Method: `POST`
   - URL: `http://<your-tagger-host>:8080/api/hooks/immich`
   - Custom Headers:
     ```http
     x-webhook-token: <Your Webhook Token from Tagger UI -> Connections -> Webhook Endpoint>
     ```
6. **Результат**. Любое новое фото с телефона получит тег `unclassified`, сразу вызовет Webhook, будет разобрано Vision LLM, разложено по альбому или убрано в архив, а тег очереди `unclassified` в конце снимется.

---

### Режим 2. Ручные теги и уже накопленная библиотека

Если хотите управлять вручную или разобрать уже лежащие фото:

- **Способ A. Ручные теги в интерфейсе Immich**
  1. Откройте библиотеку Immich в браузере или в мобильном приложении.
  2. Выберите фото, которые нужно классифицировать (или сразу день / альбом).
  3. Нажмите значок **Tag** и добавьте тег `unclassified` (или `未分类`).
  4. Если настроен Webhook `AssetTagged`, классификация начнётся сразу. Иначе их подберёт фоновый планировщик поллинга (по умолчанию каждые 5 минут). В интерфейсе Tagger можно также нажать **Сканировать сейчас** и обработать их немедленно.

- **Способ B. Дозаполнение очереди из интерфейса Tagger в один щелчок**
  1. Откройте веб-интерфейс Tagger (`http://localhost:8080`).
  2. Перейдите на страницу **Область** или **Обзор**.
  3. Нажмите **Дозаполнение очереди**.
  4. Система просканирует все объекты, которые попадают под правила области библиотеки и пути, пометит необработанные фото тегом `unclassified` и поставит их в очередь на классификацию.

## 🏷️ Справка по стандартным правилам тегов

| Тег | Тип | Действие | Целевой альбом | Мин. уверенность | Описание |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`screenshot`** | Основной | **В архив** | — | `0.80` | Снимки экрана телефона или компьютера, переписки, карты, интерфейсы приложений, игровые HUD. |
| **`document`** | Основной | Оставить на шкале | **`Documents`** | `0.75` | Счета, чеки, договоры, записи с доски, печатные бланки, страницы книг. |
| **`id_document`** | Основной | Оставить на шкале | **`ID Documents`** | `0.85` | Паспорта, удостоверения, водительские права, банковские карты, официальные документы. |
| **`meme`** | Основной | **В архив** | — | `0.80` | Реакционные картинки из интернета, стикеры, мемы с крупным текстом. |
| **`junk`** | Основной | **В архив** | — | `0.85` | Случайная реклама, значки приложений, логотипы, смазанные кадры невзначай, чёрные и белые кадры. |
| **`normal_photo`**| Основной | Оставить на шкале | — | `0.70` | Реальная съёмка (семья, портреты, питомцы, пейзажи, еда, путешествия). |
| **`other`** | Основной | Оставить на шкале | — | *(Запасной)* | Неоднозначные или многосюжетные снимки, которые нужно посмотреть вручную. |
| **`sensitive`** | Флаг | Только флаг | — | *Автоматически* | Ставится сам на документы, банковские данные, пароли или когда модель отказывается отвечать из соображений безопасности. |
| **`low_confidence`**| Флаг| Только флаг | — | *`< 0.80`* | Добавляется, когда уверенность прогноза «в архив» ниже порога, и не даёт убрать фото в архив автоматически. |
| **`needs_review`** | Флаг | Только флаг | — | *`< 0.50`* | Добавляется при очень низкой уверенности и предлагает проверить фото вручную. |
| **`refused`** | Флаг | Только флаг | — | *Автоматически* | Добавляется, когда модель отказывается отвечать (или возвращает неразбираемый вывод) и классификация не получена. По этому тегу удобно отфильтровать сбои и разобрать их вручную. |

> Запись оценки и описания тоже включается отдельно на каждом теге. В таблице выше **у тегов, которые уходят в архив, по умолчанию `write_rating: false`**, а описание всё равно пишется; остальные теги пишут и то и другое. См. ниже «Оценка / описание: отдельно на каждом теге».

## ⭐ Оценка и описание

Помимо тегов сервис может записать на каждый объект встроенные в Immich **звёздную оценку** (1–5) и **описание**. Визуальная модель возвращает их вместе с тегом, и они складываются с изменением видимости в **один запрос `PUT /assets`**: один запрос, по одной зафиксированной строке `change_log` на каждое поле. **Писать ли их вообще, решает тег** (следующий раздел). Таблица ниже описывает, что происходит *после* того, как тег это разрешил.

**Оценка значит «насколько хорошо выглядит фото»**. В расчёт идут только композиция, экспозиция, резкость фокуса, цвет, свет, заметность субъекта и аккуратность кадра. Это *не* важность, ценность как память и не эмоциональная ценность: важные люди, события и даты оценку не поднимают (имя файла и дата съёмки — только контекст). `confidence` устроен наоборот: это уверенность в *классификации*, а не в том, что фото удачное. Эти правила уже лежат в промптах по умолчанию (`autotag-config.en.yaml` / `.zh.yaml`), их можно править в **Конфигурация → Версии промпта**.

> **Обновление**. Поставляемый промпт теперь задаёт `rating` как качество снимка (раньше это была важность / ценность как память), а переключатели оценки и описания переехали из глобальной настройки в столбцы каждого тега (оба по умолчанию включены). Уже установленные копии получают новый промпт повторным импортом YAML или вставкой нового текста в **Версии промпта** с последующей активацией. Старые оценки сохраняют прежний смысл и сами не пересчитываются. Чтобы обновить их, запустите **Повторную классификацию** на затронутых объектах: это единственный путь, который переписывает значения, записанные этой системой.

Каждое поле решается само по себе (оценка и описание одного объекта могут пойти разными ветками):

| Текущее значение в Immich | Что происходит |
| :--- | :--- |
| пусто (оценки не было / описания нет) | записывается значение модели |
| совпадает с тем, что эта система записала в прошлый раз | при обычном повторном сканировании остаётся как есть; обновляется только если применение запущено явно (повторная классификация) |
| написано вами | **никогда не перезаписывается** — поле пропускается, а объекту ставится тег *флага пропуска* (по умолчанию `manual-kept`; китайское по умолчанию `保留人工信息`), пропущенное поле пишется в `change_log` |

Уже стоящее `rating = -1` считается значением (это не «без оценки»): такой объект остаётся вам.

### Оценка / описание: отдельно на каждом теге

**Писать ли оценку и описание, решает система тегов** — та же модель, что у *архива* (`archive`), *альбома* (`album`) и *пропуска Immich* (`skip_immich`). В **Конфигурация → Теги** у каждого тега две независимые галочки, **Писать оценку** и **Писать описание** (обе включены по умолчанию). Эти поля пишутся только у объектов с таким тегом. Тег со снятой галочкой ничего не пишет, ничего не кладёт в `change_log` и *не* получает тег флага пропуска. Этот флаг значит «мы хотели записать, но мешало ваше значение», а не «мы и не собирались записывать».

**Что покрывает «Пропуск»**. `skip_immich` блокирует только **теги / альбом / архив** и *не* затрагивает оценку и описание: у них свои переключатели. Обычная схема такая: у `normal_photo` включены *Пропуск*, *Писать оценку* и *Писать описание*. Настоящие фото не получают тег и не уходят в архив, но получают оценку и описание — и это единственная запись, которую такой тег делает. Чтобы какой-то класс фото в Immich не трогался совсем, выключите все три. Правила пропуска оценки и описания по-прежнему учитывают ручную правку.

**Что делает поставляемая конфигурация**. Теги, которые уходят в архив (`screenshot`, `meme`, `junk`), сохраняют описание и пропускают оценку: архив значит «спрятать с основной временной шкалы», и звёздная оценка там ни о чём, а описание всё ещё позволяет найти объект. Остальные теги пишут и то и другое. Это только стартовые значения, их в любой момент можно поменять в разделе тегов (например выключить описание у `id_document`, чтобы чувствительный текст не попал в это поле).

### `enabled_effects` (глобальные действия записи)

Каждая цель записи — независимое действие записи, но `tag`, `visibility` и `album` — это **глобальные** переключатели. Они правятся в **Конфигурация → Настройки распознавания → Действия записи и повторы** (`enabled_effects`). Всё, чего нет в списке, отбрасывается ещё при планировании: ни записи в Immich, ни строки в `change_log`. Все три по умолчанию включены.

`rating` / `description` в этот список **не** входят: они переехали в переключатели на каждом теге, см. выше. Замечание при обновлении: если в прошлой версии `rating` / `description` были убраны из `enabled_effects`, после обновления эти поля снова начнут записываться. Чтобы остановить запись, снимите переключатели на тегах.

На той же панели:

- **Имя тега флага пропуска** — тег, который ставится, когда пропущены оценка или описание, введённые вами (пусто = следовать языку интерфейса). Отдельного русского имени тега по умолчанию нет: пока поле пустое, воркер всё равно записывает китайское значение по умолчанию `保留人工信息` (английское — `manual-kept`).
- **Максимум попыток применения** — сколько раз повторять неудачное применение, прежде чем объект будет оставлен (по умолчанию `3`). Объект, который ещё ждёт повтора, показывает в карточке плашку *повтор*, а записи, которые так и не применились, попадают в список сбоев задачи.

### Опасная зона: сброс по измерениям

Опасная зона сбрасывает **четыре независимых измерения**: теги, классификацию (вернуть из архива + убрать из альбомов), оценку, описание. Рядом с каждой галочкой показано *оценочное* число затронутых объектов по локальной базе. **Трогаются только отмеченные измерения**; снятое измерение остаётся ровно как было, включая столбцы локального зеркала.

У оценки и описания есть предохранитель: поле возвращается к значению, которое было до первой записи этой системы, и только если *текущее* значение в Immich всё ещё совпадает с тем, что система записала в последний раз. Если с тех пор вы поправили его сами, сброс его не трогает (изначально пустое описание восстанавливается как `""`). Для сброса по-прежнему нужно дважды ввести `RESET`, и он отклоняется, пока активна любая задача.

## 🛠️ Продвинутые операции

- **Обработка одного объекта и песочница**. Проверьте результат промпта LLM на любом одном `assetId` в реальном времени, ничего не записывая в Immich.
- **Повторная классификация**. Если вы обновили промпт или правила категорий, запустите повторную классификацию на выбранных объектах. Система снимает прежние управляемые теги и оценивает объект заново. Это также единственный путь, который обновляет оценку или описание, записанные самой системой.
- **Откат задачи**. На вкладке **Задачи** нажмите **Откатить** у любой завершённой задачи, чтобы обратить добавление тегов, привязку к альбомам и изменения видимости за этот прогон. (Откат сброса опасной зоны возвращает теги на объектах, которыми управляла система; видимость остаётся вне архива.)
- **Сброс опасной зоны**. Отметьте одно или несколько измерений (теги / классификация / оценка / описание) и сбросьте только их. Предохранитель для оценки и описания описан выше, в разделе **Оценка и описание**. Объекты тегов не удаляются, а теги, которые вы ведёте сами на других фото, не затрагиваются.

## 🧱 Локальная разработка

```bash
# 1. Setup virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 2. Install dependencies
pip install -e ".[dev]"

# 3. Generate Immich OpenAPI client
make generate

# 4. Build Tailwind CSS
make css

# 5. Run test suite
pytest
```

Чтобы собрать образ Docker из исходников, а не скачивать готовый (тег должен совпасть с приведённым ниже, тогда `docker compose up -d` возьмёт локальную сборку):

```bash
docker build -t ghcr.io/poweredbypassion/immich-llm-tagger:latest .
```
